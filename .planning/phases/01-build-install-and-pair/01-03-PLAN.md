<objective>
Make the pairing last and make it safe to hand over: a pure-Swift flow that pairs from typed text, keeps the key out of everything except the Keychain adapter (written in Plan 04), remembers the PC across launches, classifies every half-paired state, and writes a log the user can export without ever exposing the key. All of it runs on the Linux runner, including a relaunch simulation against the real server.

Phase goal (ROADMAP, verbatim): User can build the iPhone app on GitHub Actions without a Mac, install it with AltStore, pair it with the PC by typing address and code, and see it reach the PC over plain HTTP.

Purpose: PAIR-03 (key kept, pairing remembered), BLD-05 (exportable log that never contains the device key), and the debugger-less evidence that FEAS-01 needs (a server-confirmed connection check after every launch; the one-line launch evidence record is built in Plan 04, which keeps this plan inside the context budget).
Output: `DeviceKeyStoring` protocol plus in-memory fake, `PairingStore`, `RunLog` and `PairingFlow`, with unit tests and a real-server contract test.

Reversibility: `PairingRecord` (pairing.json layout) = costly, Phases 4 to 6 read it, so it carries `schema: 1`; log file name and rotation size = reversible; the `DeviceKeyStoring` protocol shape = costly (the app adapter in Plan 04 implements it).
