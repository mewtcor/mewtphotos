<objective>
Close the phase on the real iPhone: one carefully batched session that answers the three roadmap gate conditions (the unsigned build installs with AltStore; it reaches the PC over plain HTTP; the device key survives relaunch and an AltStore refresh), exercises install-over, exports the log, and reads the true Mac-minute cost. The outcome is a written go or no-go that Phase 2 depends on.

Phase goal (ROADMAP, verbatim): User can build the iPhone app on GitHub Actions without a Mac, install it with AltStore, pair it with the PC by typing address and code, and see it reach the PC over plain HTTP.

Purpose: FEAS-01 and the device halves of BLD-04, BLD-05, BLD-06, PAIR-02, PAIR-03; BLD-07's actual billed figures. This plan adds no code layer: the end-to-end path already exists from Plans 02 to 05, and the human checkpoint here is its real-device verification, so there is deliberately no new tracer task.
Output: `docs/ios-phase1-device-test.md`, completed `01-GATE.md`.

If a gate condition fails for a reason fixable in code, this plan records NO-GO with the exact failing step and evidence lines; the fix is a new gap-closure plan (`/gsd-plan-phase 1 --gaps`) and a new Mac build, not an improvised change inside this plan.

Completion versus goal: recording `Decision: NO-GO` completes this plan, because the go/no-go note is the deliverable and a truthful NO-GO is a valid one. It does NOT mean the phase goal is achieved. A NO-GO leaves Phase 1 open: the note says `Phase goal achieved: no`, names the failing condition and the next action, and the orchestrator must route to gap closure or to an install-route re-plan instead of marking the phase complete or starting Phase 2.
</objective>

## Flagged assumptions

- AltStore Classic accepts an ipa picked from Files through the plus button, and the unsigned ipa installs (RESEARCH A2, A14). The checklist offers a second route (download the artifact zip in Safari on the phone). If neither works the condition fails and the note records the AltStore error code from its FAQ list.
- Installing a newer ipa with the same bundle identifier through AltStore updates in place (A3).
- The Keychain item and `pairing.json` survive "Refresh All" (A4); the Local Network grant may be asked again (A5). Re-prompt alone is not a failure; a lost key is.
- The PC's Windows firewall allows inbound connections to the server port on the private network. The server's own setup guide covers it; if pairing cannot connect, check `docs/troubleshooting.md` first.
- iOS 18.0 to 18.5 had a stale Local Network denial bug fixed in 18.6 (TN3179); the iOS version is recorded at the top of the checklist.
