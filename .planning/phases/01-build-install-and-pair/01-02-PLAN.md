<objective>
Prove, on a Linux runner and with no Apple hardware, that Swift code can do the one thing the phone must do first: turn a typed address and pairing code into a device key against the real, unmodified server. This is the tracer for the whole Core package; Plans 03 and 04 build the remembered-pairing flow and the SwiftUI shell on top of it.

Phase goal (ROADMAP, verbatim): User can build the iPhone app on GitHub Actions without a Mac, install it with AltStore, pair it with the PC by typing address and code, and see it reach the PC over plain HTTP.

Purpose: BLD-02 requires the iOS logic-package tests, including a contract test against the real server, to run on every push. PAIR-02 requires typed address plus code to pair.
Output: package `PhotoSyncCore` with HTTP transport, redacting `DeviceKey`, `ServerClient`, `ServerAddress`, unit tests and a real-server contract suite, all green in Actions.

Reversibility: Core wire types and the `ServerClient` surface = costly (Plans 03 to 06 and Phases 2 to 6 call them); the package layout = reversible. No door here needs a checkpoint.
</objective>

Server contract this plan consumes (extracted from server/app.ts and shared/schemas.ts, verbatim values):

GET  /api/v1/health   -> 200 {"ok": true, "name": "photosync", "apiVersion": 1}   (no auth)
POST /api/v1/pair     body {"code": string 1-32 chars, "deviceName": string trimmed 1-80} -> 200 {"token": string, "deviceId": string}
                      errors: 403 {"error":"bad_pairing_code","message":...}; 429 {"error":"too_many_attempts",...}; 400 {"error":"invalid_request",...}
GET  /api/v1/status   header Authorization: Bearer KEY -> 200 {"deviceName","serverName","chunkSize","concurrency","maxFileBytes"}; 401 {"error":"unauthorized",...}
GET  /api/v1/admin/pairing  (loopback socket and loopback Host only; TEST CODE ONLY, never called from Core) -> {"code","expiresAt","url","qrSvg"}
error body shape: {"error": snake_case code, "message": human text, ...extra}
CHUNK_SIZE = 8388608 (8 MiB). Default server port 8787 (PHOTOSYNC_PORT in server/main.ts).
Token is base64url of 32 random bytes (43 characters). The pairing code is 8 characters from a 31-symbol alphabet, upper-cased and stripped of non-alphanumerics by the server, rotates after each successful pairing.
