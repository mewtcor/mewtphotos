<objective>
Wrap the tested Core in the thinnest possible SwiftUI app and the XcodeGen spec that turns it into an installable target: a form that pairs, a Keychain adapter, a status line, the version and build on screen, and a log export control. Every decision the user cannot undo (the bundle ID) is confirmed first.

Phase goal (ROADMAP, verbatim): User can build the iPhone app on GitHub Actions without a Mac, install it with AltStore, pair it with the PC by typing address and code, and see it reach the PC over plain HTTP.

Purpose: BLD-04 (one fixed bundle ID, no extensions, no entitlements), BLD-05 (export), BLD-06 (version and build on screen), PAIR-02/PAIR-03 (typed pairing, Keychain), FEAS-01 (launch evidence and server-confirmed connection at every launch). Nothing in this plan can be compiled before Plan 05's first Mac build; the Linux gates here catch syntax, project-level policy and Photos-framework creep only.
Output: `ios/project.yml` and four Swift files in `ios/MewtPhotos/`, under 400 lines in total, plus `LaunchEvidence.swift` in Core with its Linux unit tests (moved here from Plan 03 so that plan stays within the context budget).

Reversibility ratings: bundle ID = one-way (see Task 1); Keychain service and account names = costly (changing them orphans the stored key on every installed copy and forces a re-pair); all other app-target choices = reversible.
</objective>
